# Scapare 1.1.3（8）：浏览器连续滚动衔接修复

用户在知乎页面连续滚动时遇到「这一段没有可靠衔接」，预览停在第 1 帧。原检查只有正文与固定页眉/页脚，没有覆盖同时包含滚动正文、固定侧栏和中文字体小数像素位移的视口。

## 原因与修复

- 原匹配将固定侧栏的纹理也计入正文位移，密集边缘验证会否决正确衔接。现在选取分布在多行、确实发生变化的列，让固定侧栏不参与位移投票。
- 局部动画会让整幅画面的像素一致率下降。现在按空间分块验证，要求同一位移与相位在至少三个纵向区域、足够多的内容块上成立。限制单块的权重，避免一个密集动画区域压过正常正文。
- 中文深色字形在小数物理像素位移下，其粗匹配误差可能超过原阈值，尚未进入精确验证就被拒绝。搜索描述使用轻量纵向平滑，精确验证以 1/8 像素的相位步长处理重采样。输出图片仍使用原始捕获像素。
- 继续使用连续 ScreenCaptureKit 视频帧；没有重新加入等待静止帧的条件。无重叠、歧义重复纹理和输出尺寸上限仍会保留此前结果并提示恢复。

## 验证

143 项回归检查通过，双架构 Release 构建成功（Apple silicon、Intel）。

- 修复前，新增加的「滚动正文 + 固定侧栏」用例报 `noOverlap`；修复后连续追加，正文逐像素等于原文档。
- 覆盖固定侧栏、固定导航、局部动画、动画但正文未滚动、快速位移、向上回滚后继续向下、跳过重叠区域，以及原有复制/取消/重试流程。
- 使用实际字体绘制 3349 × 1936 像素中文浏览器视口，覆盖加速、小数像素位移及 16 种参考帧/下一帧相位组合。整数位移的正文逐像素核对，没有重复或漏行。
- 本机优化测试中，11 次上述中文视口匹配与追加约 38 毫秒；包含生成测试画面约 268 毫秒。该数字不包含真实屏幕采集，不是实际链路稳定帧率的承诺。
- Developer ID 签名有效，保留 App Sandbox，未包含 `get-task-allow` 调试权限；应用身份继续为 `com.gaoyiming.SnapTool`。
